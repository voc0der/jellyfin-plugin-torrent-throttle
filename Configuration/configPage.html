Torrent Throttle

Reserve bandwidth for remote Jellyfin streams by adjusting qBittorrent speed limits.

Applies your upload cap while idle and reduces it during remote playback. Disabling restores the previous qBittorrent limits.

qBittorrent connection

Must be reachable from the Jellyfin server or container. Include a reverse proxy path if needed. Use HTTPS when the connection crosses an untrusted network. Self-signed certificates are accepted only for private and loopback IP addresses.
qBittorrent 5.2 or newer. An API key takes precedence over username and password. Credentials are stored in Jellyfin's plugin configuration.

Tests network access and credentials without changing speed limits.

Bandwidth budget

The starting cap before subtracting remote streams. 1 MiB/s = 1024 KiB/s ≈ 8.39 Mbps. Both normal and alternative speed profiles use this budget while enabled.
Subtract the same playback bandwidth from the download cap. Leave off to let qBittorrent manage its own download limits.
Default: 5. For transcoding, starts when an output bitrate becomes available. A stream that stops before the delay ends does not reduce the cap.
Added to reported stream bitrates to allow for buffering and network overhead. This is a bitrate estimate, not a measurement of total WAN traffic.
Used when a stream's bitrate is unknown. Transcode metadata gets up to 30 seconds to arrive before the settling time begins. Local playback is excluded using Jellyfin's network settings.
